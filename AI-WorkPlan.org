* Stage 2: The blee gitGroup --- Rules, Status and the Magit List

<<Stage 2>>

Goal: repeat for blee what bisos-pip/overview has: a gitGroup plant whose rules every blee repo
follows (checked and applied with gitist's engine), and the gitGroup's cached list for Blee's Magit
menu. Two overviews make the pattern.

Decided (user, 2026-11-15):
- *Not a package.* An overview of a gitGroup that is not pip packages stays outside packaging: the
  plant is =py3/bin/blee_gitGroup.spcs= here, and bsip4's =bin/= (=/bisos/core/bsip/bin=, always on
  PATH on a BISOS host) has a symlink to it,
  =/bisos/git/bxRepos/blee/overview/py3/bin/blee_gitGroup.spcs=.
  (bisos-pip's overview stays a pip package: its gitGroup is pip packages.)
- *=.spcs=*: the plant is spread-planted --- gitGroup name and base come from where it really lives
  (the symlink resolved): base = the overview repo's parent, name = its name. It declares only its rules.
  gitist's =gitGroup_seedInfo.setup()= gains this (gitist WorkPlan 7.8); bisos-pip's explicit =.pcs=
  is unchanged (a pip script may run from a copy whose path says nothing).
- *Rules*: root =.gitignore= = =gitignore/emacs+py+tex= (as bisos-pip); *no* =.gitattributes= rule
  (the only template, =gitattributes/py=, marks all but =*.py= as vendored --- elisp would vanish from
  GitHub's language statistics); no generated-files rule (no =py3/README.rst= here).
- *Cached list*: =/bisos/var/gitGroup/blee/cachedList.auth=, the =blee= collection repo included; Blee's
  Magit menu lists it with no change (gitist 7.7).

Survey (2026-11-15; 40 member repos): =.gitignore= 32 missing, 5 the shared old copy (as 44 bisos-pip
repos had), 3 unique; =.gitattributes= (not a rule) 6 present.
